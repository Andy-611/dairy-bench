# V9 架构与不变量

[English](ARCHITECTURE.md) | [简体中文](ARCHITECTURE.zh-CN.md)

## 1. 模拟边界

当前场景 `flow.dairy.base.s9.v9` 包含 3 家牧场、3 家加工商、3 家零售商和
52 个七日经营周。权威决策链路是：

```text
Wake -> AgentTurn -> CompanyDecision -> EconomyEngine -> Journal -> next Wake
```

Runtime 负责身份、时间、状态版本和提交顺序；只有 `EconomyEngine` 能修改现金、
库存、订单、任务、运输、价格和销售。

## 2. 模块职责

- `domain/models.py`：不可变的场景、观察、事件、周报、快照和评分契约；
- `economy/engine.py`：经济状态转移与周结算；
- `economy/consumer.py`：隐藏经营周期、有限消费者群组和共享市场分配；
- `economy/ledger.py`：供周报和 Agent 私有经济视图共同使用的强类型事件账本；
- `economy/private_view.py`：公司私有累计现金流与可执行单位经济性；
- `economy/reports.py`：权威的私有周报与公开零售市场周报；
- `economy/oracle.py`：按 Seed 计算全信息企业总盈余参考值；
- `runtime/episode.py`：调度、并发推理、确定性提交、恢复和 Replay；
- `storage/repository.py`：狭窄的原子持久化 Interface；`storage/memory.py` 和
  `storage/sqlite.py` 是两个 Adapter；
- `agents/providers/newapi/`：唯一模型传输 seam，内部按配置、HTTP Transport、Wire
  Protocol 和 Decision Gateway 分层。

依赖方向始终指向强类型领域契约；Web、存储和 UI 只能投影事实，不能修改经济状态。

## 3. 每周经营周期

周一开启新周，并实现每家生产企业私有的周产能和单位成本。周一至周六允许生产、
批发交易、加工和运输；每家公司每天最多一个经营 Turn、每周最多六个。

周日固定执行：

1. 完成到期任务和运输；
2. 关闭两个批发订单簿并释放未成交抵押；
3. 为所有存续零售商生成采购后的定价上下文；
4. 让所有零售商基于同一个定价前状态并发决策；
5. 每家提交一个价格，全部返回前互相不可见；
6. 对有限的共享消费者市场统一结算一次并计入销售收入；
7. 计提每家存续零售商的周运营费，并优先用现金支付；
8. 删除到期库存，再执行本周最终破产检查；
9. 生成周报并保存周快照。

周日定价只能调用 `set_retail_price`，且不占六个经营 Turn。模型没有返回合法价格时，
系统保留上周价格；第一周使用 `3.5000`。该次协议错误会被完整审计，物理轨迹仍继续，
但结果只能用于诊断，不能进入正式模型排名。

## 4. 共享消费者市场与信息边界

市场由三个有限的支付意愿群组构成。每周消费者优先购买自己能够接受的最低价商品；
最低价缺货后流向下一低价；同价零售商使用确定性等额分配，只有无法均分的
`0.0001` 尾差按 Seed 哈希分配。

市场在低迷、正常、旺盛状态间切换。每个状态持续 6～10 周；正常状态与极端状态
交替，低迷和旺盛也在连续的极端阶段间交替。状态同时改变总需求、消费者构成和
WTP；每个 Run 还有一个全程固定的隐藏购买力偏移。购买力偏移取
`-0.2/-0.1/0/0.1/0.2`，低迷/正常/旺盛状态再分别叠加 `-0.2/0/+0.2`。

Agent 会知道：

- 存在三个支付意愿不同但参数未知的消费者群组；
- 最低价优先、缺货溢出和同价分配规则；
- 三个状态名称、6～10 周持续时间及交替结构；
- 状态可能同时改变市场规模、消费者构成和 WTP，整体购买力也可能改变 WTP。

Agent 不会知道：各群组基础数量、准确 WTP、购买力/状态偏移、状态构成倍率、
第一个极端状态、当前状态和切换周。完整 `ConsumerMarketSpec` 只属于经济引擎；观察中仅包含
`ConsumerMarketRules`。

## 5. 周报与学习信号

每次观察最多包含本公司最近 8 个已完成周的私有周报，以及最近 8 个公开零售市场
周报。

私有通用字段包括期初/期末企业价值、当周和累计盈余、现金、应付运营费、采购、
批发销售、经营成本、过期损失和按到期周拆分的账面库存。角色专属字段包括：

- 牧场：实现产能/成本、产量、产能利用率、原奶已售与未售数量；
- 加工商：原奶采购、加工量、实际得率、产能利用率、盒装奶产出、销售与库存；
- 零售商：采购数量和 VWAP、可售库存及加权成本、零售价、销量、收入、COGS、毛利和营业利润、
  售罄率、是否售罄、市场份额、过期损失和期末库存。

公开周报展示每家零售商的状态、公开价格、销量、市场份额和是否售罄，以及市场总
销量和成交量加权均价。竞争者现金、成本、采购和准确库存仍为私有；未满足的真实需求
永不公开。

## 6. 物理与会计规则

- 牧场正常产能为 `60`，加工商正常投入产能为 `50`。三家合计形成 `180` 的原奶供给
  缓冲和 `150` 的加工投入；乘 `0.8` 得率后，正常盒装奶产能恰为 `120`，与正常三档
  消费需求一致。每周私有值由 Seed、持续性、波动和上下界实现；
- 凸成本函数为 `C(x)=c*x+curvature*c*x^2/(2*K)`；
- 加工得率为每单位原奶产出 `0.8` 单位盒装奶；
- 原奶和盒装奶分别经历 2、4 次周结算后到期；
- FEFO 抵押与运输保留 Lot 来源、到期周和账面成本；
- 买卖单全额抵押，按价格—时间优先，以 Maker 挂单价成交；
- 所有经济价格、数量、价值和成本统一使用 `0.0001` 精度，零售价没有独立精度规则。
- 每家存续零售商在周日销售收入入账后计提 `5.0000` 运营费；现金不足部分形成应付，
  并从企业价值中扣除。

## 7. 确定性、并行与恢复

同一天被唤醒的 Agent 观察同一个提交前状态，并发推理后按以下顺序串行提交：

```text
SHA256(seed | absolute_day | company_id)
```

周日定价也共享同一个观察状态，所有价格提交完成后才执行消费者分配。因此供应商响应
速度不能改变经济结果。

每个 `RunJob` 拥有独立的 Runtime、Scheduler、经济状态、策略实例、Journal 和
Checkpoint。原子进度事务支持中断恢复。Replay 会重新执行源决策；观察、协议回退、
结果、事件、快照、分数或质量任一漂移都会失败。

启动脚本只有在 `/api/health` 的 API、场景、评分、数据库和 Journal Payload 契约全部
匹配时才会复用已有后端；端口 8000 上的旧 Checkout 会被明确报告为冲突。

V9 使用 `runs-v9.sqlite3`，数据库 Schema 为 16，Payload Schema 为 10。Repository
只接受当前契约，不包含旧版 Runtime 数据库的迁移或读取器。

## 8. 破产

权威企业价值包括现金、按参考价计算的自有/抵押库存、在途采购和已付款任务的保证
产出，再扣除应付运营费。净值严格小于 `1.0000` 才破产；恰好等于 `1.0000` 仍存续。破产不可逆，会撤单、删除
零售价、取消未来 Wake，并只产生一个破产事件。

## 9. 评分

对于已经完整结算的第 1 周至第 T 周（T <= 52）：

```text
E_raw    = sum_i [V_i(T) - V_i(0)]
E_oracle = 当前 Seed 下的全信息企业总盈余参考值
E        = clip(E_raw / E_oracle, 0, 1)
G_all    = Gini(V_1(T), ..., V_9(T))
F_all    = clip(1 - G_all / (8/9), 0, 1)
L        = count_i[V_i(T) - V_i(0) < 0]
P        = 1 - L/9
Score    = 100 * E * sqrt(F_all * P)
```

`V_i(T)` 是现金加按固定参考价计量的期末库存，再减应付运营费。Oracle 使用相同的
实际产能/成本路径、凸成本、加工得率、保质期、实现后的隐藏 WTP、共享消费者、
零售运营费和期末参考价值；目标只包括企业总盈余，
不包括消费者剩余。求解结果向上加入很小的安全边际，避免数值误差低估参考值。

`D` 是破产企业数量；`L` 只统计严格负盈余企业；盈余等于零属于不亏损，因此计入
`P`。结果栏只展示 `D` 和 `L`；`D` 始终是数量而不是破产率。

`RunEvaluationProjector` 通过同一个接口读取正式完成结果或最新的持久化
Checkpoint。running、stopped、interrupted 和 failed 状态只要至少完成一周，
就能展示截至最近完整结算周的阶段评估；当前半周的事件、Turn 和 Token 均不
计入。Oracle 使用相同的 T 周期限。阶段分数标记为 provisional，不进入正式
排名；第 52 周的不可变 Episode 仍是唯一正式结果和 Exact Replay 来源。

## 10. 必须保持的不变量

1. 标准 Episode 恰好完成 52 次周结算和 52 个快照；
2. 经营 Turn 只发生在周一至周六，周日只增加密封零售定价；
3. 每个零售商在共享结算前最多提交一次价格；
4. 隐藏需求参数不得进入 Agent 观察或 Prompt Payload；
5. 周报只能来自已经完成的过去周，滚动窗口最多 8 周；
6. 共享销量与输入顺序无关，且不得超过库存或消费者总量；
7. Job、运输、Review 和批发挂单不得跨周；
8. 只有经济引擎能修改状态，Journal/Checkpoint 必须原子提交；
9. 同状态并发推理加确定性提交保证供应商时延不影响经济结果；
10. 扣除应付后的净值严格小于、而非等于 `1.0000` 时立即且永久破产。
